## 开发期间暴露的问题

| 本地运行 | 结果与发现 |
| --- | --- |
| `qwen-00a07cb8` | 首轮预算耗尽；Planner 重复部署，Executor 尝试不同工具 |
| `qwen-90178f8f` | 旧验收器曾报告 10/10；加强留出复核后只有前五轮有效，A3 漏了 limit 上界，不能作为最终通过证据 |
| `qwen-68053b53` | 加强验收后 7/10；A4 错误修复循环耗尽预算，B5/A5 阻塞 |
| `qwen-da0e9c72` | 事实摘要调整后的开发运行仍为 7/10；没有用标准补丁替换失败模型结果 |
| `qwen-0ce49635` | 最终代码上下文格式及修复诊断提示下 10/10；独立重评仍为 10/10 |

修正的机制包括：

1. 给角色明确当前任务的已完成动作和动态允许能力，旧经验不充当当前执行证据。
2. 对工具路由别名做显式协议映射，保存原始模型返回。
3. 区分“成功复现”与“服务已经正确”；每次变更后重新 probe，即使回到曾见过的哈希。
4. 将运行异常作为带版本的工具观察回传，允许在预算内继续修复。
5. 公开回归增加默认分页、limit 上界、布尔类型；留出验证换数据和参数。
6. 记忆事实摘要依据可执行验收目标生成，模型自由总结只保留供审计。
7. 给模型展示正常换行的代码块，替代 JSON 中转义的源码；补丁带简短诊断，仍由模型生成。

这些是开发改进，不可把调整前后不同系统版本的耗时直接当作同条件性能对比。
